## 1. Pourquoi spec sans code

Hierarchical HMM (HHMM) est un modèle canonique en :
- **Bioinformatique** : phonèmes → syllabes → mots
- **Activity recognition** : poses → mouvements → actions
- **Finance** : micro-régimes intra-journaliers → macro-cycles
- **Speech** : sons élémentaires → segments → énoncés

C'est un modèle puissant et bien étudié (Fine, Singer & Tishby 1998 — l'article fondateur). Aucun outil Python ne l'implémente proprement aujourd'hui (vérifié dans l'audit du 2026-05-22).

**Mais** : c'est ~3-4 semaines d'effort solo part-time, et le gain ne se
matérialise que si un utilisateur extérieur le demande explicitement. Sans
signal, ce serait du "build it and they will come" — exactement l'antipattern
qu'on a refusé en début de session.

**Décision** : on rédige le spec maintenant (gratuit en temps Claude, et ça
nourrit le wedge "tool taken seriously by academics"), mais on **ne livre
pas le code** tant que les critères d'entrée ne sont pas réunis.

## 3. Pour mémoire : formulation math

Histoire que le spec ne se périme pas (le savoir vaut quelque chose).

### Notations

- Hiérarchie à L niveaux : niveau 0 (root) → niveau 1 → ... → niveau L-1 (production states)
- À chaque niveau, un état interne **produit** un sous-HMM enfant
- États terminaux (production states) émettent une observation comme dans un HMM standard
- Transitions horizontales **dans** un niveau : matrice $A^{(\ell)}_{ij}$
- Transitions verticales : `produire un enfant` ou `retourner au parent`

### Forward-backward hiérarchique

L'algorithme forward-backward classique est généralisé en :
- **Multi-scale forward** : pour chaque sous-HMM, calculer alphas conditionnellement à l'instant d'activation
- **Multi-scale backward** : symétrique
- **Inside-outside** : pattern emprunté aux PCFG, applicable ici

Complexité exacte : $O(T \cdot |\Sigma|^L)$ où $|\Sigma|$ = nombre d'états par
niveau. Pour L=2 (niveau racine + production), K=4 par niveau → 16 × T
opérations — gérable. Pour L=3 et K=5 → 125T, encore OK. Au-delà, il faut
des approximations.

### Référence : Fine, Singer, Tishby 1998

*The hierarchical hidden Markov model: Analysis and applications*. Machine
Learning 32, 41-62. Article fondateur, derivation complète, identifiabilité
discutée.

### Référence Murphy 2002

Kevin Murphy a une thèse / chapitre dédié sur HHMM avec dynamic Bayesian
networks comme cadre unifié. Plus moderne, plus extensible. Recommandé
comme référence d'implémentation si le code est jamais écrit.

## 4. Pour mémoire : API publique projetée

### YAML topology pour HHMM

```yaml
name: speech_hhmm_demo
type: hierarchical                   # type top-level
levels:
  - name: phoneme
    n_states: 3
    state_names: [silence, vowel, consonant]
    emission:
      type: gaussian
      covariance_type: diag
      n_features: 13                 # MFCC
    transitions:
      type: ergodic
  - name: syllable
    n_states: 4
    state_names: [onset, nucleus, coda, end]
    contains: phoneme                # un syllable est un sous-HMM de phonemes
    transitions:
      type: left_right
  - name: word
    n_states: 5
    contains: syllable               # un word est une séquence de syllables
    transitions:
      type: ergodic
fit:
  algorithm: baum_welch_hierarchical
  n_iter: 200
```

### Python API projetée

```python
from hmm_core.fit import fit
from hmm_core.io import load_topology

topo = load_topology("hhmm_speech.yaml")
result = fit(topo, X)

# Decoded path retourne une trajectoire hiérarchique
decoded = result.decode_hierarchical(X)
# decoded.levels[0] = trajectoire phoneme
# decoded.levels[1] = trajectoire syllable
# decoded.levels[2] = trajectoire word
```

## 5. Pour mémoire : architecture d'implémentation

Si jamais on l'implémente :

- **Nouveau backend** : `NumpyHHMMBackend` dans `backends/`. C'est le bon
  endroit. hmmlearn ne supporte pas HHMM, donc impl pure numpy.
- **Topology étendue** : nouveau type `HierarchicalTopology` qui contient
  une liste de `LevelTopology`, chacune ayant ses propres états + transitions
- **Forward-backward implémenté en pure numpy log-space** pour la
  stabilité — éviter underflow critique en HHMM à L≥3
- **Decoding hiérarchique** : Viterbi modifié qui produit une trajectoire
  par niveau
- **Validation V.7** dans la suite scientifique : reproduire les exemples
  du papier Fine/Singer/Tishby 1998 à 1e-4 près

## 7. Risques et notes pour le futur implémenteur

- **EM convergence** plus délicate (deux niveaux de latence × hiérarchie)
  → multi-start + warm-start depuis HMMs par niveau
- **Identifiabilité** : permutation entre niveaux possible, contraintes
  d'identification nécessaires
- **Mémoire** : pour L=3, K=5, T=10000 → tenseurs intermediaires multi-niveaux
  peuvent grossir. Stocker en streaming si nécessaire.
- **Cas dégénéré** : si tous les sub-HMMs ne sont jamais activés, modèle
  effondre vers HMM plat. Warning si on détecte ce cas (signal de sur-spec).
